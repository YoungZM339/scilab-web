# 故障排查

先保护数据，再处理服务。任何涉及升级、恢复、卷或数据库的操作，都应先运行 `./ops/backup.sh`；如果数据库已经异常，不要反复重启或删除卷。

## 快速收集状态

```bash
./ops/status.sh
docker compose ps
docker compose logs --tail=200 app
docker system df
```

求助时请提供版本或 commit、上述输出、操作步骤和预期结果。先移除域名中的敏感信息、邮箱、Cookie、密钥、数据库内容和上传文件。不要上传 `.env`、数据库或完整备份。

## 容器无法启动或一直 unhealthy

1. 运行 `docker compose config --quiet` 检查配置。
2. 查看日志中最早出现的错误，而不只是最后一行。
3. 确认 `.env` 中的认证密钥不少于 32 个字符，两个 URL 都是完整 Origin。
4. 使用 `df -h` 和 `docker system df` 检查磁盘空间。
5. 若错误发生在 migration，停止尝试升级，保留日志并按部署前备份回滚。

不要通过删除数据库、数据卷或 migration 表来“修复”启动问题。

## 无法登录后台

- 确认访问的是 `/admin/login`，浏览器地址与 `BETTER_AUTH_URL` 的协议、域名和端口一致。
- 公网环境必须使用 HTTPS，并检查反向代理是否保留 Host、Origin 和转发协议头。
- 忘记密码时使用 `pnpm admin:reset-password`；重置会撤销现有会话。
- 连续失败后等待限流窗口结束，不要持续自动重试。
- 修改认证密钥后，所有旧 Cookie 都会失效，需要重新登录。

## 修改后公开页面没有变化

- 确认已经保存，且内容状态为“已发布”。
- 研究方向或成果若要进入主页，还需选择“重点展示”。
- 用无痕窗口排除管理员会话和浏览器缓存影响。
- 检查内容关联的图片或 PDF 是否仍存在且允许公开访问。

## 图片或 PDF 无法上传

- 检查后台提示的文件类型和大小限制，不要只修改文件扩展名。
- 图片损坏、格式不受支持或 PDF 内容与扩展名不符时会被拒绝。
- 使用 `df -h` 检查宿主机及 Docker 数据目录空间。
- 已被内容引用的文件不能直接删除；应先移除引用并确认公开页面不再使用。

## 备份失败

- 先运行 `./ops/status.sh`，确认应用和数据库健康。
- 确认 `SCILAB_BACKUP_DIR` 是安全、可写且空间充足的目录。
- 查看备份日志中的一致性检查或媒体校验结果；校验失败时不要覆盖旧备份。
- 至少保留一份最近验证过的异地备份，再排查本机存储。

## 磁盘空间不足

优先把经过验证的历史备份迁移到加密异地存储，并检查日志、旧镜像和构建缓存。不要直接删除 Docker volume、当前数据库、`uploads/` 或不明用途的 WAL/SHM 文件。清理 Docker 资源前用 `docker system df` 确认对象归属。

## 恢复后仍不健康

保持应用停止，保留恢复脚本输出中列出的 `.ops-restore-*`、`.ops-rollback-*` 和安全备份。不要再次运行恢复覆盖现场。记录当前代码版本、目标备份名和完整日志，按照[运维文档](operations.md)核对代码版本与数据库版本是否匹配。
